# Reproducing the trial-table diagnostic

Run `python reproduce.py` from this directory (Python 3.10 or newer, standard library only). The independent cohort is in `independent/`. Its 320 raw model calls support a separately scored 80-statement test on 20 previously unscored trials. `results/independent_predictions.csv` gives Direct, Select and the two fallback rules.

The command verifies the frozen input and method hashes, the archived request bodies and model digests, and the logical costs and labels for Direct and Record-LLM. It scores the archived outputs and writes `results/`. No model server or network is required. `expected.json` checks the contents of the independently regenerated results. CSVs use simple headers, contain one model and method per row, and can be opened in a spreadsheet.

- `data/confirmation.jsonl` and `data/dev.jsonl` are the label-free inputs. `freeze.json` pins the extraction code, model digest manifest and inputs before new inference. The fixed development round contains one statement from each of 20 trials. There are 40 development and 160 confirmation calls. The 80 confirmation inputs are reused for post hoc diagnosis.
- `method.py`, `run.py` and `legacy/` are the unedited frozen protocol and parser. Run `python fresh_run.py OUTPUT_DIRECTORY` to collect a new set from a local Ollama server with the pinned digests installed. It writes a separate folder and checks existing receipts if resumed. It does not replace the frozen replies. `run.py prepare` was a workspace-specific assembly step and is unnecessary for replay.
- `data/model_config.json` contains model variant, quantization, templates, system messages and local runtime version. The original service metadata for older runs is in `historical/config/`. Only the local filesystem prefix from an autogenerated model-build path was removed when preparing the shareable metadata. We have no service patch identifier for every cached request.
- `logs/` contains the request, full model reply, weight digest, recorded request seconds and token counts for each fresh row-selection call. `historical/` provides the original claim extractions, Direct and record-judge calls used in the comparison, two-pass control receipts, historical scored items, source checks, condition-test inputs and label corrections. `historical/adapters/` contains the archived confirmation decompositions and checks. Hashes of externally retrieved materials and pointers are in `historical/source_evidence/`. The raw registry studies cited in the ledger are retrievable through `https://clinicaltrials.gov/api/v2/studies/{NCT_ID}`. Existing public dataset and source terms apply.
- `results/comparison.tex` and `results/stages.tex` are the manuscript's two main results tables. `results/predictions.csv` and `.jsonl` contain 1,440 item-method predictions (2 models × 80 statements × 9 methods). `results/metrics.csv` includes mismatch precision, recall, F1, false-alarm rate, accuracy, coverage, paired intervals, changes against Direct, calls, tokens and summed request seconds. The repaired methods reuse old calls. Fallback costs include both components for every sample. These times are not a hardware speed benchmark.
- `results/audit.jsonl` records the run-time first failure, overlapping offline differences in the original fields, all returned row IDs and the set of permitted target IDs. All constructed confirmation statements have one target relation. The row check uses every parsed row and compares normalized identity and reference reporting conditions, without reading the row value. An extra or repeated selection fails exact row scoring. Both the returned row's identity and the final class can be inspected independently of whether the reply was valid. `results/failure.json` gives totals. The old validated-field comparison checks mismatching relation count first and does not align fields of variable-length lists. `results/cases.json` links examples to exact statements and source rows. No original confirmation claim was lost to broken JSON syntax. Synthetic outer fences on the fixed development statements are tested as interface examples only.
- `results/public_scope.jsonl` links all 26 point-shaped public statements to their passages and item-specific scope decisions. `historical/public.jsonl` contains the 150 public inputs. The scope check uses neither predictions nor labels and was made after the main evaluation. It counts extension to multiple rows as direct lookup if the claim names the rows and the quantities share the reported units. A conversion, a different measured quantity, an altered regimen or a change derived across visits is coded separately. `results/label_ledger.jsonl` identifies affected statements and retained labels. `results/sensitivity.json` removes all unresolved statement IDs within each cohort while preserving the main analysis.

The historical clamp on numeric syntax and the old adapter diagnostics are retained for provenance. Only the new comparison and its companion analyses are regenerated by the root command. Hashes and manifests refer to bytes of delivered inputs. The paper, not the archive, is the conference submission PDF.

The follow-up audit in `paired_audit.py` compares the two fallback procedures directly and identifies which trial and type each gain came from. `results/paired_audit.json` also records two implementation boundaries. The frozen protocol summary lists quotation validation before completeness, whereas the row selector executable checks completeness first. On six incomplete Qwen confirmation replies, a later invalid quotation can also be identified. These six are not counted twice in the runtime table. The original executable gives conflicting numerical values within a candidate pool whole-statement precedence, but an explicitly ambiguous row ID is unresolved only within its relation. A separate ambiguity-first check yields exactly the same development and confirmation classifications for both models. The synthetic input documents where the two rules differ. A genuine output-format failure in the new diagnostic is in the Llama receipts for `a5609dfa3c368b39` and `6b9e077e8959fe60`, both truncated. The original 160 confirmation claim extractions all parsed as JSON. The example JSON fence is synthetic.


For the independent evaluation, `independent/freeze.json` pins the trial split, source snapshots, publication screens, prompts, model digests and scoring logic before the 320 new calls. `independent/logs/` holds all 80 receipts for each model and method. `results/independent_metrics.json`, `independent_predictions.csv` and `independent_table.tex` report all 80 statements for each model. `independent_stages.jsonl` identifies first failures and the secondary ambiguity-priority comparison. `independent_rows.jsonl` applies the original row-scoring definition after inference. It records the compatible and returned row IDs independently of the final verdict. `independent_source_audit.json` checks the 40 paired inputs against archived trial tables. The two items whose common source excerpt contained an NA cell are retained. The original 80 statements and the new 80 come from disjoint trials with the same two templates. Scoring uses the frozen inputs. Run `python cohort_source/rebuild.py` to repeat the selection and pair construction offline. The script verifies the checksum of `independent/construct.py` and supplies it with the archived screening decisions, registry records and helper functions. `cohort_source/helper_provenance.json` identifies the archived module and original function names, and `cohort_source/checksums.json` lists the supplied file hashes. Of the 20 selected trials, 10 had known publication links at construction. With the later archived PubMed checks, 12 had known links. The script checks both stages separately. For the 620 studies outside the eligible pool, the archive preserves the original screening decisions and the identification and publication-reference fields used by the constructor. Full result fields are included for the 78 candidates. Replaying an original live database search and running fresh model inference are separate from reproducing the reported analyses.

`audit_counts.py` replays the 80 reference-input construction checks and all 95 accepted historical extractions from their archived replies. `results/paper_counts.json` reports the overlap of condition and identity/value differences, the relation-count differences, the size of the earlier exclusion pool and the distinction between an incomplete reply and its first recorded failure on the independent set.

`validation_order.py` replays the written validation order on each archived selector reply. It checks source parsing and response syntax, validates all row IDs and field types, then checks numeric values, value quotations and condition quotations before testing completeness. It treats explicit ambiguity as grounds to abstain on the whole statement. Candidate lookup and value comparison reuse the frozen judge. This post hoc check produces `results/validation_order_items.jsonl` and `results/validation_order_summary.json`. Fallback comparisons use the archived Direct answers for the two evaluation sets. The development round used selection only. The synthetic boundary checks are separate from the 360 real replies.

The no-conditions comparison in Section 7.2 uses the historical presence-matched rule. `condition_ablation.py` reads the initial claim replies, applies the same validity checks and heading inheritance as Joint, and compares condition presence while ignoring condition values. Its 160 predictions in `results/condition_ablation.jsonl` are checked against the archived decisions. The legacy `no_conditions` branch predates this correction.
